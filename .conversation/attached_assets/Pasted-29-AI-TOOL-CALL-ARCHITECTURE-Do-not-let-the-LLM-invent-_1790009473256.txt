29. AI TOOL-CALL ARCHITECTURE

Do not let the LLM invent numerical answers.

Implement tools/functions conceptually like:

get_enterprise_risk()
get_top_risk_drivers()
get_asset_risk(asset_id)
get_vulnerability_risk(vulnerability_id)
get_risk_trend()
run_scenario(parameters)
optimize_budget(budget)
get_compliance_status(framework)
get_control_effectiveness(control_id)
get_business_unit_risk(unit_id)

The LLM calls these tools and explains their results.

If no LLM API is available, implement deterministic intent matching for the demonstration questions.

Modeled EAL reduction:

36. VISUAL DESIGN

This is extremely important.

The application should look like a premium cybersecurity enterprise product.

Use:

dark navy / near-black background
subtle blue/cyan accents
white/gray typography
limited use of red/orange only for risk states
glass-like cards where appropriate
subtle borders
strong spacing
clean typography
modern icons
smooth transitions

Avoid:

excessive gradients
cartoonish illustrations
huge neon elements
clutter
excessive rounded cards
generic Bootstrap appearance

The visual style should resemble a combination of:

enterprise security operations software
financial risk analytics
modern SaaS
executive intelligence dashboard
